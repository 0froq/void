Components read the twelve tokens on `.ui`. They do not add that class themselves.

## Principles

Coherence over decoration. Type, spacing, radius, and highlight say the same thing wherever they mean the same thing. A deliberate contrast is fine. Unintentional drift is not.

Restrained surface. What a person meets stays small, with strong defaults. Configuration stays underneath, in props, tokens, and source.

Aesthetics are a constraint. A state that only works by breaking the surface does not ship that way.

## Chrome

### Radius

- Controls, about 2px. `--ui-radius`. Framed fields and buttons.
- App rows, about 8px. A product tier. Not a library token.
- Cards, about 10px. A product tier. Not a library token.

Menu and Select lists are control-tier surfaces. Here that means a hairline and radius 0, the list lig uses in its header. They do not take the 2px control radius, and they do not take the card radius.

### Elevation

Menu and Select lists have no soft shadow. The hairline is the edge.

### Highlight

One language. The highlighted row is underlined: 1px, offset 4px, no fill, no accent bar. The current row keeps a 5px accent dot in the start gutter. Select draws it for the checked option. Menu draws it when the item content has `aria-current="page"`.

### Type

- `--ui-font-display` — Instrument Serif. Voice.
- `--ui-font-text` — Geist. Text.
- `--ui-font-meta` — Geist Mono. Labels. Menu and Select lists are 11px meta.

The project loads the fonts. The package does not.

### Scope

The variables live on `.ui`. Import `@froq/ui/style.css` with the components, or `@froq/ui/tokens.css` for the variables alone. A portaled menu uses the nearest `.ui`, so the list keeps that region's colors.
